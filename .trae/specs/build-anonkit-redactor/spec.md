# AnonKit 本地文档脱敏桌面工具 — Product & Technical Spec

## Why

律师、法务、企业合规人员经常需要把含敏感信息的合同、底稿、披露文件交给 AI 或外部协作方处理，但客户隐私不允许外传。市面上的独立脱敏工具普遍存在：只做脱敏不做还原、简称/非结构化敏感信息漏检、性能差、无法保留原文档格式、中文场景支持弱等问题（详见 `参考资料.md` 的分析）。本产品提供一个**完全本地运行、开源、高性能、可还原**的文档脱敏桌面工具，让用户完成"扫描 → 确认 → 脱敏 → 送 AI → 还原"的完整闭环。

## What Changes

- 新建跨平台桌面应用 AnonKit（Windows + macOS），技术栈 **Tauri 2 (Rust) + Python sidecar**。
- 提供**四层检测**：正则规则（结构化 PII）、词典匹配（自定义实体/敏感词）、上下文规则（关键词增强置信度）、本地中文 NER 小模型（可选下载增强）。
- 提供**完整脱敏策略集**：掩码/占位符/假数据三类输出，内置 21 类策略（对标 sensitive-spring-boot-starter），支持自定义策略、自定义替换符、AES/DES/BASE64/RSA 可逆加密。
- 提供**全文一致性替换 + 映射表还原**：同一实体全文统一替换，session 内可一键还原，支持"简称/代词关联"（如"北京降本增笑有限公司"→"降本增笑"全文联动）。
- 支持 **PDF / Word (.docx) / TXT / MD** 首版格式（PDF 保留版面脱敏），扩展格式（PPT/XLSX/HTML/RTF/OCR）列入后续阶段。
- 内置**模型下载管理器**：应用内点击下载 NER 模型到程序数据目录，断点续传；默认不下载（纯规则模式零依赖即可用）。
- 提供 **"扫描预览 → 人工确认 → 脱敏导出 → 一键送 AI → 还原"** 的完整工作流，支持批量文件处理与审计日志。
- 提供**质量门禁（golden corpus）**：内置真实形态脱敏测试集作为每次发版门槛，P0 类型（手机/身份证/银行卡）召回 ≥99%、P1 类型 ≥95%，杜绝规则变更引发回归（对标 docs-anonymizer）。
- 提供**漏检 / 冲突提醒**：预览页醒目提示疑似漏脱、占位符冲突与词典定义冲突（对标墨盾），降低"以为脱敏了其实漏了"的风险。
- 开源发布：**Apache-2.0**，第三方依赖全部选用 permissive 许可（MIT/BSD/Apache/MPL），明确排除 AGPL 依赖以保障商用。差异化定位：**跨任务持久化映射还原**（.anonymap，可选口令）优于同类"仅 session 内还原"方案，作为对外宣传点。

**BREAKING**: 全新项目，无既有代码兼容负担。

## Impact

- Affected specs: 无（新项目）。
- Affected code: 新仓库 `AnonKit`，包含 `src-tauri/`（Rust 核心）、`sidecar/`（Python 文档解析 + NER）、`src/`（Web UI）、`crates/`（独立引擎库）。

## Architecture

```
┌──────────────────────────────────────────────┐
│ Tauri 2 主进程 (Rust)                         │
│  ├─ 正则规则引擎 (regex crate, 多线程)         │
│  ├─ 词典 / 上下文规则 / 映射表管理             │
│  ├─ 批处理调度 (rayon 并行)                   │
│  ├─ 模型下载管理器 (reqwest, 断点续传)         │
│  ├─ 配置 / 审计日志持久化 (SQLite)            │
│  └─ sidecar 生命周期管理 + IPC                │
├──────────────────────────────────────────────┤
│ Web UI (React + 本地渲染)                     │
│  拖拽导入 / 扫描预览高亮 / 确认 / 导出 / 还原   │
├──────────────────────────────────────────────┤
│ Python sidecar (PyInstaller 单文件, FastAPI)  │
│  ├─ 文档解析: PDF (pypdfium2/BSD)             │
│  │            DOCX (python-docx/MIT)          │
│  ├─ NER 推理 (onnxruntime, INT8 量化)         │
│  └─ OCR (Tesseract, 后续阶段)                 │
└──────────────────────────────────────────────┘
```

- sidecar 通过本地 HTTP (`127.0.0.1:随机端口`) + JSON 通信，由 Rust 主进程拉起/守护/停止，断网零外传。
- 文档解析统一输出**结构化文本 span**（含文档内位置信息），Rust 侧做检测与替换决策，Python 侧做格式读写，职责分离。

## ADDED Requirements

### Requirement: 结构化规则检测

系统 SHALL 内置高精度的正则规则引擎，在纯 CPU 上多线程并行扫描，覆盖中国大陆的手机号、身份证号（18/15 位 + 校验）、银行卡号（Luhn 校验）、固定电话、车牌号、电子邮箱、IP、金额、日期等类型；每条规则可独立启用/关闭/调整。

#### Scenario: 常规文本检测
- **WHEN** 用户拖入一个含"13800138000"的 TXT 文件并触发扫描
- **THEN** 系统识别出 1 处"手机号"命中，在预览中高亮显示，类型标注准确

#### Scenario: 规则开关
- **WHEN** 用户在策略设置中关闭"金额"类型
- **THEN** 后续扫描不再对金额类文本产生命中

### Requirement: 词典与上下文规则检测

系统 SHALL 支持用户维护敏感词典（人名、公司名、项目代号、地址等），词典词在全文做精确匹配；SHALL 支持"关键词上下文"规则（如"身份证号："、"甲方："后的内容提升置信度）；词典与上下文规则协同识别纯正则无法覆盖的简称与非标实体。

#### Scenario: 简称联动
- **WHEN** 文档包含"甲方：北京降本增笑有限公司（以下简称"降本增笑"）"且后续正文多次出现"降本增笑"
- **THEN** 系统识别"北京降本增笑有限公司"全称并将简称"降本增笑"作为关联实体，预览中一并标出，提示用户可统一脱敏

### Requirement: 本地 NER 小模型增强（可选下载）

系统 SHALL 提供模型市场：用户可在应用内点击下载中文 NER 模型（ONNX INT8 量化，单文件 ≤120MB，spike 实测选型 `protectai/gyr66-bert-base-chinese-finetuned-ner-onnx`，Apache-2.0，CLUENER 标签集），下载到应用数据目录（支持断点续传、校验和校验、可删除）；下载后检测层自动增加人名/机构名/地名识别。**默认下载后启用**（spike 实测人名 F1 1.0、机构+词典兜底 0.93+，纯规则模式人名漏检严重，NER 为默认检测层之一而非仅增强）。检测层固定顺序：正则（结构化 PII）→ 词典（全称/简称）→ 上下文规则（"以下简称"学习）→ NER 兜底人名/机构。

#### Scenario: 下载模型
- **WHEN** 用户进入"模型市场"点击某模型的"下载"按钮且网络中断后恢复
- **THEN** 下载进度条继续推进（断点续传），完成后模型出现在"已安装"列表并可启用

#### Scenario: 零依赖运行
- **WHEN** 用户从未下载任何模型，直接拖入文档扫描
- **THEN** 扫描正常完成，仅依赖规则/词典/上下文检测，应用不发起任何网络请求

### Requirement: 多策略脱敏与自定义

系统 SHALL 提供三类脱敏输出（掩码 `138****8000`、类型占位符 `[手机号1]`、假数据 `13900001111`），内置策略覆盖中文姓名、身份证、手机号、电话、地址、邮箱、密码、车牌、银行卡、金额、日期、IP、URL、组织机构、通用文本；SHALL 支持自定义替换符（默认 `*`）、自定义策略（保留前 N/后 M 位、正则替换、词典替换、加密算法 AES/DES/BASE64/RSA 可逆脱敏）。

#### Scenario: 自定义替换符
- **WHEN** 用户将替换符从 `*` 改为 `■`
- **THEN** 掩码输出变为 `138■■■■8000` 形式

#### Scenario: 加密脱敏
- **WHEN** 用户对"身份证号"选择 AES 加密策略并配置密钥
- **THEN** 输出为密文，且系统记录密钥标识，支持在还原流程中解密恢复

### Requirement: 全文一致性替换与还原

系统 SHALL 在单次任务内为每个实体建立统一映射表（原文 ↔ 占位符），全文（含跨文件批量场景）使用同一映射，保证同一个人/公司/号码始终替换为同一占位符；任务完成时提供可持久化的映射文件（含口令保护选项），用户可将 AI 或外部处理结果再次导入，一键还原。

#### Scenario: 一致性
- **WHEN** 合同正文 3 处出现"张三"、批量文件集中 5 处出现同一手机号
- **THEN** 所有出现均替换为同一个占位符（如 `[人名1]`、`[手机号1]`）

#### Scenario: 还原
- **WHEN** 用户将脱敏稿 + AI 返回结果导入"还原"入口
- **THEN** 占位符被替换回原文，输出还原后文档/文本

### Requirement: 多格式文档支持（MVP）

系统 SHALL 支持 PDF、Word (.docx)、TXT、MD 的导入与脱敏副本导出，原文件永不改动、始终输出新副本；PDF 脱敏采用 **spike 已验证的内容流级删除**：pypdfium2 提取 span/bbox → pikepdf 编辑页面内容流删除命中文本的 Tj/TJ 算子（字节级删除，脱敏区域不可再被选中/复制）→ 追加白底矩形 + 原位重绘掩码文本（双保险，保留版面）；对跨块敏感串/非常规字体编码（WinAnsi/GBK）等无法精确删除的边界场景，回退"覆盖级"并在导出摘要中**明示该 PDF 为"覆盖级脱敏"**；DOCX 保留格式替换 run 文本；TXT/MD 直接重写；文档元数据（作者、属性）在导出副本时清除。

#### Scenario: PDF 脱敏
- **WHEN** 用户对一份 30 页 PDF 执行脱敏导出
- **THEN** 新 PDF 中所有命中的敏感文字变为掩码文本且版面位置/字体大小与原稿一致，原 PDF 不变

#### Scenario: DOCX 脱敏
- **WHEN** 用户对含表格、页眉的 DOCX 执行脱敏
- **THEN** 正文、表格单元格、页眉页脚中的命中文本被替换，其余样式原样保留

#### Scenario: 原文件保护
- **WHEN** 用户对任意受支持格式执行脱敏
- **THEN** 原文件未被修改，输出带 `_脱敏` 后缀的新副本

#### Scenario: PDF 脱敏深度
- **WHEN** 用户对 PDF 执行脱敏导出后，在阅读器中尝试选中/复制脱敏区域
- **THEN** 若为内容流级删除，该区域无文本可取；若回退覆盖级，导出摘要已明确提示"覆盖级脱敏"，不静默交付

### Requirement: 扫描预览与人工确认工作流

系统 SHALL 提供"导入 → 扫描 → 预览确认 → 导出"的交互流程：预览页按命中分组展示（类型/文档/页码），高亮原始上下文，每条命中可单独勾选/取消，支持按类型一键全选/取消；未确认命中默认不执行替换。预览页 SHALL 同时提供**漏检 / 冲突提醒**：检测到疑似漏脱（已知命中邻近出现未识别的人名/简称）、占位符编号冲突或词典定义冲突时，顶部以提示条醒目列出并可跳转定位。脱敏完成后展示审计摘要（处理文件数、命中数、按类型统计、耗时）。

#### Scenario: 人工确认
- **WHEN** 扫描发现 50 处命中，用户取消勾选其中 2 处疑似误报
- **THEN** 导出副本中仅 48 处被替换，2 处保留原文

#### Scenario: 批量处理
- **WHEN** 用户一次导入一个含 20 个 docx/pdf 的文件夹并确认
- **THEN** 系统并行处理，全部输出脱敏副本，并显示每文件状态与审计摘要

#### Scenario: 漏检与冲突提醒
- **WHEN** 词典同时定义"降本增笑"与"北京降本增笑有限公司"且全文映射可能冲突，或命中附近出现未识别的疑似人名
- **THEN** 预览页顶部出现冲突/漏检提示条，说明原因并提供处理建议，不静默通过

### Requirement: 性能目标

系统 SHALL 满足以下性能指标（普通 x86/Apple Silicon 笔记本，纯 CPU）：
- 规则检测：10MB 纯文本全文扫描 < 1s（Rust 多线程）；
- NER 增强：100 页合同（约 10 万字）< 10s（ONNX INT8 + 512 token 分块 + 并行推理）；
- 批量：8 个 20 页 PDF 并行脱敏 < 20s（解析 + 规则检测 + 重写）；
- 应用启动：< 1.5s（Tauri 冷启动），空闲内存 < 120MB（不含 sidecar 惰性启动）。

#### Scenario: 大文件不卡 UI
- **WHEN** 用户扫描一份 50MB 大文件
- **THEN** 界面保持响应，任务以进度条异步展示，可随时取消

### Requirement: 隐私与零外传

系统 SHALL 保证文档内容在检测/脱敏/还原全过程中不离开本机：运行时不做任何遥测/上报，唯一网络用途是模型市场下载与版本检查（均可关闭）；sidecar 只监听 `127.0.0.1` 随机端口；构建时通过冒烟测试断言核心引擎不发起外部 socket；前端渲染层启用 CSP `default-src 'none'` + `connect-src 'none'` 作为运行时纵深防御；原文档仅在内存或受控临时目录中处理，任务结束即清理，不落盘于普通目录。

#### Scenario: 断网可用
- **WHEN** 用户完全断网状态下执行完整"扫描→确认→脱敏→还原"
- **THEN** 全部功能正常（除模型下载外），无任何报错或降级

### Requirement: 审计日志

系统 SHALL 在本地记录审计日志（时间、文件、命中类型与数量、采用的策略、输出路径），仅保存在本机，用户可查看/导出/清空。

#### Scenario: 审计追溯
- **WHEN** 用户查看审计日志
- **THEN** 可按日期/文件筛选，每条记录展示脱敏统计摘要

### Requirement: 开源与许可合规

系统 SHALL 以 Apache-2.0 许可开源；第三方依赖仅使用 permissive 许可（MIT/BSD/Apache/MPL），维护"依赖许可清单"文档并纳入 CI 检查，禁止引入 AGPL/GPL 依赖（含传递依赖）。PDF 处理采用 pypdfium2/pdfium-render（BSD）而非 PyMuPDF（AGPL）。

#### Scenario: 许可检查
- **WHEN** 开发者新增一个第三方依赖
- **THEN** CI 中的许可证检查任务执行，若发现 GPL/AGPL 则构建失败并提示替换方案

### Requirement: 质量门禁（golden corpus）

系统 SHALL 维护 golden corpus（真实形态脱敏测试文档集，含中文姓名、公司全称与简称、手机号、身份证、银行卡、邮箱、地址等，跨 PDF/DOCX/TXT/MD），在 CI 与每次发版前全量回归，作为门槛：P0 类型（手机号、身份证号、银行卡号）召回率 ≥99%，P1 类型（人名、机构、地址、邮箱、电话）召回率 ≥95%；同时校验脱敏副本版面/样式一致性。任何检测规则、词典或 NER 模型变更不得造成既有样本回归。

#### Scenario: 发版门槛
- **WHEN** 开发者提交涉及检测能力的变更并触发 CI
- **THEN** golden corpus 全量回归执行；任一 P0 样本召回低于 99% 或出现历史回归则构建失败

## MODIFIED Requirements

无（全新项目）。

## 后续阶段（不在 MVP 验收范围，作为 roadmap 记录）

- 扩展格式：PPTX / XLSX / HTML / RTF / CSV。
- 扫描件 OCR：接入本地 Tesseract（Apache-2.0），识别扫描 PDF 与图片。
- 企业能力：策略模板库共享、团队词典同步（本地文件导入导出）、更细粒度权限。
- 深挖还原安全性：映射文件加密、脱敏强度分级（可逆/不可逆提示）、加密本地保险库（AES-256-GCM + 恢复口令，对标 anonym.plus）。
- 中文 NER 自训练管线：基于脱敏场景标注数据微调，持续提升简称/非标实体召回。
- MCP Server：向 Cursor / Claude Desktop 等 AI 工具提供脱敏/还原能力（对标 anonym.plus 与 CloseMask 的网关思路），呼应"脱敏应嵌入 AI 流程"的产品判断。
